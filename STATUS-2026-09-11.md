## 2. Diagnosis — what needs fixing, in order

### Blockers before anyone pays (do these first)

1. **The Stripe webhook can lose a paying customer.**
   `netlify/functions/stripe-webhook.js:40` awaits the Supabase upsert and
   never checks `res.ok`, then returns 200 to Stripe regardless. If the write
   fails, Stripe never retries and the customer never becomes Pro. Fix: check
   `res.ok`, return 500 on failure so Stripe retries, log the body.
2. **Cancelled subscribers keep Pro forever.** Only `checkout.session.completed`
   is handled. Add `customer.subscription.deleted` and
   `invoice.payment_failed` → set `is_pro=false`.
3. **Two webhook implementations exist** (Netlify JS, live per `netlify.toml`;
   Supabase Deno function, dormant). Delete the dormant one so they can never
   both grant.
4. **`ManageSubscription.jsx` is a mock.** "Annual plan · $59.99/yr" (real
   price is $34.99), "Renews March 14, 2027", card "•••• 4242", a CANCEL button
   with no handler, and copy that says billing is through the App Store. Replace
   with the real entitlement row (plan, period end) and a link to the Stripe
   customer portal, or hide the screen until then.
5. **Analytics are dead.** `trackEvent` only fires if `window.plausible`
   exists. The Plausible tag lives in `app/+html.tsx`, which the Expo export
   ignores (proof: zero occurrences in `dist/index.html`), and its domain is
   `trainingmode.co` while the app is served at `apptrainingmode.com`. Inject
   the tag from `scripts/copy-public-assets.mjs` with the right domain. Until
   this is done the launch cohort is invisible.
6. **No crash reporting.** Add Sentry (free tier) in the same injection step.
   A JS error in the wave is currently unobservable.

### Should fix before the user wave

7. **Notifications do nothing.** The ENABLE NOTIFICATIONS toggle sets a
   localStorage flag and never asks the browser. `reminderEngine.js` computes
   reminders that nothing delivers. Either wire Web Push (service worker
   `showNotification` + a scheduled sender) or relabel the screen as in-app
   reminders so users are not misled.
8. **TM-19 stray "x"** before TODAY'S BOUT: `HomeDashboard.jsx:240` renders an
   emoji in Press Start 2P, which has no emoji glyph. Wrap the emoji in a
   system-font span. Same in `screenGuides.js:46`.
9. **"CLEAR L3 FIRST"** copy still verbatim in `TrainingCampMap.jsx:457`.
10. **"Coming soon" strings** still in Practice Mode (`PracticeMode.jsx:816,848`),
    Arcade series detail, Fight hub, and a screen guide. Hide until real.
11. **Initial bundle is 5.3 MB of JavaScript** (`entry-*.js`). First load on
    mobile data is slow. Route-level lazy loading exists for some screens;
    move the campaign data files (3 files over 1500 lines) and Practice content
    behind dynamic imports.
12. **Fonts load from Google Fonts at runtime.** In the sandbox the request
    failed and text fell back; on a bad connection the first paint flashes.
    Self-host the three families in `public/fonts`.
13. **Cloud sync reload mid-session.** `cloudSync.js:233` reloads the page when
    the cloud copy is newer, without checking whether a session is live. Guard
    on `ACTIVE_SESSION_SCREENS`.
14. **Duplicate data module.** `fit-mode/combatConditioningData.js` and
    `data/combatConditioningData.js` are different files with the same name.
    Pick one.
15. **`public/pip-test.html`** is a dev page shipped publicly. Remove after the
    phone test is done.
16. **Onboarding tour is still ~15 coach marks**; AN-03 asked for 3–4.

### Verified fine

Session survival, paywall gates (arcade stage 4+, camp level 4+, second
routine), Stripe payment links and prices, RLS on entitlements (select-only
for clients), sync backup/restore, PWA manifest and icons, service worker
(network-first navigations, build-stamped caches, no `skipWaiting`), privacy
page, share cards, challenge links and QR, ghost battles, streaks.

Not verifiable from this environment: offline start (the service worker
deliberately does not register on localhost), automatic PiP on a phone, GPS
outdoors, real TTS loudness. All four have a one-step check listed in their
prompts.

## 3. Two weeks to profitable with 50–100 users

"Profitable" here means revenue above the hosting bill (Netlify + Supabase +
domain, roughly $0–30/month), which at $5.99/month or $59 lifetime is a
handful of paying users. The real goal is 50–100 **active** users with a
working payment path, so the number that matters is paying conversions and
week-2 retention, not signups.

### Week 1 — make money possible and make it observable

Day 1–2 · Fix items 1–6 above. Flip `PAYWALL_ENABLED` in Stripe test mode,
buy a test plan end to end, cancel it, confirm Pro turns off. Then live mode.
Day 3 · Deploy from `app`, clear the PWA cache, install to Home Screen, run the
three phone checks: `/pip-test.html` auto-open, a 1-mile GPS run, a phone call
mid-round.
Day 4 · Founder offer: the $59 lifetime link is already built. Make it the
headline for the first 100 users ("Founder · lifetime · price goes up at 100").
Scarcity you can actually honour beats a discount.
Day 5 · Fix 8–10 (an hour), remove `pip-test.html`, self-host fonts.
Day 6–7 · Recruit the first 20 by hand. You already have a QA tester
(Usama) and a beta feedback form. Message every combat-sports contact,
gym, and coach you know personally with the install link and the founder
price. Ask each for one session and one voice note of feedback.

### Week 2 — get to 50–100 and keep them

- **Share cards are the growth loop.** They are built and verified. Add the
  founder link and the app URL to every card so a screenshot on Instagram
  or a gym group chat is an invitation. Post your own daily session card.
- **Challenge links** (`/?ch=…`) are built. Run a "beat my Stage 3" thread in
  one Discord or subreddit for boxing/kickboxing fitness. One good thread
  brings 30–50 installs.
- **Coaches sell it for you.** Three gyms or coaches who assign Fight Focus
  or Combo Coach as homework is 30–60 users. Offer coaches free Pro and a
  code for their athletes.
- **Retention.** Fix notifications (item 7) or, if Web Push is too big for the
  window, ship the in-app reminder card (`getDashboardReminder` has no caller
  today) and a daily streak email via Supabase auth emails. Watch the
  Plausible `session_complete` count per user; anyone with two sessions in
  week one is worth a personal message.
- **Measure five numbers weekly:** installs, sign-ins, sessions per user,
  paywall views → checkouts, week-2 return rate. Plausible has them once the
  tag is live.

### What not to do in these two weeks

No new modes. The app has ten. The native wrapper, friend ghosts by username,
recorded voice cues, and the Workout Codex are all real but none of them
brings a paying user faster than the six blockers above.
